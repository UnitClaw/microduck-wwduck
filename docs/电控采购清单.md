## 先搞清楚：板子都装在哪

这一条直接影响你买什么规格的线，**很容易搞错**：

```
头（MJCF 里的 jaw_soft 刚体）
 ├── Raspberry Pi 形态主控板     ← 主控在头里，不在躯干
 ├── RPI Robot HAT               ← 叠在主控上方 7.3 mm
 ├── IMX219 摄像头 + M12 镜头     ← 距主控板中心约 13 mm，同一刚体，中间没有关节
 └── 喇叭

躯干（trunk_base）
 ├── 两颗 hip_yaw XL330          ← 内腔基本被这两颗占满
 ├── trunk_base 底板
 └── NP-F 电池 —— 外挂在机身后下方，71 mm 长有约 40 mm 悬在壳体外，
      由两片 power_support 从外面夹住

穿过三自由度脖子的是：舵机总线 + 从电池上来的 +BATT 供电线
```

**证据**：`robot_walk.xml:235` `mesh="elec_rpi_robot_hat_pcb"`、`:247` `mesh="pcb__raspberry_pi_zero_2_w"`
两个 geom 都在 `jaw_soft` body 内；两块 65×30 板 X/Y 完全对齐、Z 间距 7.3 mm，是标准的 Pi + HAT 叠层。

> ⚠️ **所以 MIPI 排线不过脖子，买最短的就够。** 真正的线束疲劳风险在**舵机总线和电源线过颈**上
> —— 那是承流线，风险比信号排线更值得重视。而官方**没有公开任何走线资料**。

## 一、主控 · Radxa Zero 3W

### 该买哪个配置

> 📌 **勘误（2026-10-12）**：这里原来的结论是「2G / 16G eMMC」，**这个建议错了，让大家多花了钱**。
> 官方资料只写了 **1 GB 内存、32 GB 存储**，并没有说是 eMMC；我们自己的第一台用的就是
> **2 GB、无 eMMC、插 microSD 卡**的裸板，跑 kissqy 整套系统实测只用了 175 MB 内存、3.3 GB 存储。
> 已经按旧建议买了 2G/16G 的照样能用，只是多花了钱，不用换。

**结论：1G 或 2G 的「无 eMMC」裸板，再配一张 32 GB microSD 卡。**

| 配置 | 够不够 | 说明 |
|---|---|---|
| **1G / 无 eMMC** + microSD | ✅ 够 | 和官方同一档（官方：1 GB 内存、32 GB 存储） |
| **2G / 无 eMMC** + microSD | ✅ 更宽裕 | 我们第一台就是这个；以后开摄像头、跑检测模型更从容 |
| 带 eMMC 的（8G / 16G / 32G…） | 能用，没必要 | 贵一截，存储一张卡就够了 |

**实测**（2026-10-12，第一台：2G / 无 eMMC / 64 GB microSD，跑 kissqy 整套 + 50 Hz 控制循环 + 蓝牙手柄）：
内存已用 **175 MB**（可用 1.79 GB），存储已用 **3.3 GB**。当时没接摄像头，摄像头服务没开；
开了以后 GStreamer 和检测模型会多占一些内存，1 GB 仍有余量。

**microSD 卡**：买正规品牌（闪迪、三星等）、标 A1 或 A2 的 32 GB 卡。别买杂牌低价卡：
系统盘出问题时，症状往往像别的故障，很难查。

下面是当初分开估存储和内存的过程，结论已经被上面的实测替代，留作参考：

**存储侧**

| 项 | 体积 | 依据 |
|---|---|---|
| Armbian headless rootfs | ~2 GB | `deploy/README.md:144` 确认是 headless 镜像；**2 GB 是外部经验值，仓库无依据** |
| **ONNX Runtime** | **~20 MB** | `docs/design/robotd-design.md:420` 原文：「ONNX Runtime is a board prerequisite … **~20 MB** in every artifact would enlarge every update for nothing」——**板级预装，不在 release 包里** |
| **GStreamer 栈**（`mediad` 用） | **~100 MB** | `docs/design/updater-design.md:901`「the GStreamer stack for `mediad`, which is **around 100 MB of apt**」 |
| RKNN 运行时 `.so` | 未知 | 仓库无依据，不编数字 |
| daemon 制品 + 保留的一份旧版本 | 量级 10¹ MB | `Cargo.toml:79`「**model artifacts will dwarf a few MB of binary**」；`keep_previous = 1` |
| **9 个运动策略 ONNX** —— 每个 **793,685 B ≈ 775 KiB** | **7 MB** | 实测。`alpha_stand` / `alpha_walking` / `alpha_sitstand` / `alpha_ground_pick` / `ball_kick_left` / `ball_kick_right` / `roller` / `roller_crouch` / `roulade` |
| `duck_detect.onnx` | 10.0 MB | 实测 10,477,940 B |
| `pet_detect.onnx` | 19 KB | 实测 20,201 B |
| journald 上限 `SystemMaxUse=200M` | **默认配置下不占盘** | `/var/log` 是 zram 设备（`deploy/README.md:14/402/437`）。但 README:454 给了退路：关掉 `armbian-zram-config` 后日志就落到 eMMC |
| **合计** | **≈ 3 – 4 GB** | |

→ 当初估 3–4 GB，**实测 3.3 GB**。一张 32 GB microSD 绰绰有余，**不需要 eMMC**。

> 💡 **升级机制不需要双份 rootfs。** 但**别叫它 A/B** —— 上游 `docs/design/updater-design.md:46`
> 专门澄清过：「Update granularity | **Application-level (not A/B image)** | Only daemon + model
> change; OS is static. A/B (RAUC/Mender) would be over-engineering.」
> 实际是**版本目录 + `current` 符号链接原子切换（`rename(2)`）+ 健康门禁 + 回滚**，
> `keep_previous = 1` 只多留一份旧 daemon。（`updater.toml` 的 `tag_prefix` 实际值是 `daemon-v`。）

**内存侧**

| 项 | 占用 |
|---|---|
| Armbian headless | ~250 MB（外部经验值） |
| robotd + ONNX Runtime + RKNN | 小 —— 策略模型只有 775 KiB/个 |
| 摄像头 / GStreamer 缓冲 + `duck_detect` | ⚠️ **`duck_detect.onnx` 跑 CPU 不跑 NPU**（`robotd.toml:324`「a `.rknn` runs on the NPU, an `.onnx` on the CPU」；NPU 版 `.rknn` 不在仓库里）。且 **RK3566 的 NPU 与 CPU 共用 DDR，没有独立显存** |
| ⚠️ `/var/log` 的 zram 设备 —— **吃 RAM 不是盘** | 需预留 |

→ 当初估「1 GB 能跑但紧」，**实测整套只用 175 MB**。1 GB 够用，2 GB 更宽裕，再大没必要。

> **官方配置**：Pollen 新闻资料包写的是「**1 GB RAM、32 GB storage**」，没写是 eMMC 还是 SD 卡
> （此前本文写成「1 GB / 32 GB eMMC」，多加了 eMMC，已更正）。`microduck/` 源码里也查不到板卡 SKU。

## 四、ToF 测距 · VL53L5CX 或 VL53L8CX（8×8 多区）

**固件只认这两颗，没有第三个。** `tof/src/sensor.rs` 里就一个 match，按 revision ID 分：

```rust
match revision_id {
    0x0C => L8cx,
    0x02 => L5cx,       // 官方注释：「大多数在用的鸭子装的就是这颗」
    _    => Unknown,    // 没有驱动，直接报错退出
}
```

认不出来时守护进程的原话是 `… which is neither a VL53L5CX nor a VL53L8CX`，然后退出。
固件里只编了两个 ULD 驱动 shim（`Driver::L5` / `Driver::L8`），别的芯片连驱动都没有，改 ID 也骗不过去。

I²C 地址候选 **`0x29` 或 `0x52`**（`tof/src/main.rs:107`，0x52 是官方原型机为了给 IMU 让地址挪过去的，
挪过的传感器掉电还在 0x52），挂在 i2c3 @ 400 kHz。HAT 上走 **JST SH 1.0 mm 4P**（Qwiic / Stemma QT）接口 J5–J8。

### 板子尺寸决定能不能塞进脸壳

同样是能用的芯片，模块板型差一倍多。脸壳（`face_part`）的 ToF 开孔是按特定板型做的，换板型就得改图：

| 模块 | 芯片 | 板子尺寸 | 重量 | 参考价 | 结论 |
|---|---|---|---|---|---|
| **VL53L5X V2 模块** | VL53L5CX | **15.8 × 10 mm** | 1.15 g | ¥44.5（带盖片 ¥49.5） | ✅ **首选**：固件认，板子最小，还最便宜 |
| VL53L8CX 模块（国内常见板型） | VL53L8CX | 33.4 × 10.2 mm | 1.7 g | ¥75 | ⚠️ **不推荐**：芯片没问题，但这块板 33.4 mm，脸壳装不下（2026-09-20 实测）。除非你找得到更短的 L8CX 板，或者愿意改外壳 |
| VL53L7CX 模块 | VL53L7CX | 26 × 11.5 mm | 1.3 g | ¥75 | ❌ **别买**：固件直接报错退出 |

**打印件的孔距是 20 mm，只有 L5CX 那块板对得上**（同事 2026-09-20 实测：打印件孔位 20 mm，

### imu_to_dxl —— 自绘

STM32G031F8P6 + LSM6DSV16X + 半双工缓冲，对外表现成总线从机（Dynamixel 侧 ID 200）。
协议与寄存器布局已完整还原，见 [硬件方案逆向](硬件方案逆向.md)。

- **打样成本**：2 层板，嘉立创约 ¥25–40（不含贴片）
- **双协议**：要同时支持飞特与 Dynamixel 的话，**硬件不变、固件分支** ——
  两者物理层完全相同（半双工单线 TTL / 1 Mbps / 3 线），差别只在包格式
  （V2 包头 `FF FF FD 00` + CRC-16；飞特 `FF FF` + `~sum`）
- ✅ **接口与脚序已由官方规格书确认** —— 飞特《HL-2915-C002 串型规格书》A/0（2026-02-27）
  第 4 页 6-7 项：连接器 **`AMP-3`**，**`1=GND / 2=Vcc / 3=Signal/TTL`**，与 Dynamixel 一致。
  `HD-1910-C001.stp` 里连接器零件名为 `AMP-3P`，且该装配体含 `HL-2915-C002_ASM`，两款共用平台。
  <br>同规格书还确认：半双工异步、8bit/1stop/无校验、**出厂默认 1 Mbps**、ID 0–253（默认 1）、
  信号高电平 **2–5 V**（本板 74LVC 输出 3.3 V 在窗口内；输入耐 5.5 V 也扛得住舵机的 5 V）
  <br>⚠️ 该规格书是 HL-2915-C002（**12 V**），电气参数不可套用到 HD-1910（5–8.4 V）
  <br>⚠️ 「飞特 = TTL 单线」只对 STS/SCS/HL 成立 —— 官方手册写明 **SMS 系列走 RS485、默认 115200**
- **连接器壳体仍要实物试插** —— 飞特线材标 **5264 端子**，官方 HAT 用 **JST EH**，
  两者**都是 2.5 mm 间距**但不同系列，卡扣和壳体外形不同。舵机和线到手后试插一次，
  插不上就把 J1/J2 从 `B3B-EH-A`（`C160259`）换成 5264-3P。
  PR #12 那版图上是 JST PH 2.0 mm，**间距就不对，要改**
- **C6（LDO 输入电容）耐压 10 V → 25 V** —— 总线满电 8.4 V，10 V 余量不够（MLCC 还有直流偏压衰减）
- **C5 用 4.7 µF 不是 100 nF** —— ST DS12992 Rev 3 Fig.13 对 `VDD/VDDA` 的要求是
  `1 × 100 nF + 1 × 4.7 µF`，两颗一样的 100 nF 并联不顶用。选立创基础库 `C19666`
- **U1 的 2、3 脚留有源晶振焊盘（不贴）** —— TSSOP20 没引出 `OSC_OUT`，无源晶振接不了；
  HSI16 精度最坏 −1.85%/+1.55%（Table 41），1 Mbps 够用但余量不多
- **DATA 线加 TVS** —— 带电插拔舵机是常态
- **协议靠软件自动识别，不加拨码开关/跳线** —— 两家包头都是 `FF FF`，Dynamixel V2 后面跟 `FD 00`，飞特跟的是 `ID`+`LENGTH`（LENGTH 恒 ≥ 2，所以 `FD 00` 无歧义）。收前 3 包投票锁定，之后按锁定协议收发。拨码开关在会走路的机器人里是振动失效点，而且这板一辈子只配一次
- **J3 用 6P 不用 4P** —— 多出的 4/5 脚是 `USART1_TX/RX`（U1 脚 16/17 重映射），插个 5 块钱 USB-TTL 就能看 printf。G031 没有 USB 外设，加 USB 口要多一颗桥接芯片，不值
