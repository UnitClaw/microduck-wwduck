# 主仓结构件与 CAD 版本核对（2026-09-28）

**核对结论：原先没有完全对齐。** 主仓的打印 STL、装配预览和训练几何来自上游 XL330 模型；CAD 仓库已发布飞特 v2.1。旧文件不能直接当成最新飞特 CAD 的打印导出件。

**按用户确认后的处理方式：模型直接指向配套 CAD 仓库。** 主仓已移除 `print/` 的 45 个旧单件 STL、`cad/` 的 16 个装配 STL 与旧对照表，这两个目录改为下载入口；中英文首页、BOM、采购说明与署名同步调整。旧文件可从 Git 历史追溯，模型的后续版本统一在 [microduck-wwduck-cad](https://github.com/UnitClaw/microduck-wwduck-cad) 维护。

CAD 仓库的说明同步修正：XL330 打印入口不再跳回主仓旧 STL，改指向本仓 v1.1 源文件；09-15 3MF 与旧 BOM 的版本边界也已标明。本轮只修改该仓 README，没有更新 CAD、3MF 或工作簿。

本轮没有重新导出或重排 CAD / 3MF，也没有替换训练、网页模型及物理参数。分析导出脚本默认写入被忽略的 `analysis-output/cad-upstream/`，避免重新生成一套主仓下载文件。以下保留修改前的检查证据，经独立 agent 复核。

下表将主仓单件 STL 与 CAD 仓库现有 3MF 中对应 STEP 来源网格比较，旧 STL 的米制坐标先统一转换为毫米。独立复核确认所列网格均为闭合且有效的体积；这些差异说明不是仅仅改名或导出文件格式不同。

## v2.1 与打印包还有两处要分清

1. **合体轮胎属于轮滑变体。** v2.1 发布说明是将分开的 `rim` 和 `tire` 合并为 TPU 合体轮胎；不能据此说走路整机所有零件都在 09-25 改过。
2. **CAD 仓库 3MF 没跟上这项变更。** 远端与本地 3MF 的 Git blob 都是 `796b092c754e8c7041a4ca5495d01757c56c5266`；`Metadata/model_settings.config` 仍有轮辋 4 个、轮胎 4 个，没有合体轮胎。该 3MF 不能称为 v2.1 完整打印包。本轮未另外验证 MakerWorld 在线工程是否更新。

另外，已下载并核验 v2.1 的 10 件 STEP 包：SHA256 为 `57dd4a2a191bedbf01a4916bc4df34bba6c175793b532ebecc7a1e1aed8c2ca0`，与 GitHub 附件 digest 相符。和 v2.0 的 9 件包逐个比较：

- **7 件内容相同**：加固板、`99-yaw_roll_motion`、压盖、左右上腿、飞特小腿、`yaw2roll`。
- **新增 3 件文件**：飞特左踝、右踝、合体轮胎。
- **包内不再包含 2 件**：无 `-FT` 后缀的小腿和 `trunk_base_躯干底座-FT.STEP`。

因此“9 个 STEP 加一只轮胎”不足以完整描述附件变化；缺少的躯干底座 STEP 不能被理解成该实体零件已取消。完整 SolidWorks v2.1 装配引用本轮没有逐件打开验证，后续导出时应检查。

## 后续真正修改模型时的核对事项

本次用户选择统一到 CAD 仓库维护，不在主仓另造打印包。**（2026-10 起主仓 `print/` 已重新承载飞特「缝合怪版」打印件，见 [print/README](../print/README.md)，与 CAD 仓库可编辑源文件互补。）** 后续若更新 CAD 仓库或训练模型，仍需核对以下事项：

1. 在 CAD 仓库明确 XL330 与飞特版本，避免两套舵机的配合件混用；主仓保持链接入口。
2. 以 CAD v2.1 全套源文件为基准建立零件映射，先核对走路用的踝、小腿、加固板、压盖、左右上腿和躯干安装件，再单独处理轮滑合体轮胎。
3. 从确认后的 CAD 导出 STL，核对单位、左右件、孔位和数量，再更新 3MF、BOM 与下载入口。不能只把旧 STL 改文件名或把链接改成 v2.1 就算完成。
4. 最后更新装配预览和网页模型；训练侧要另外校准关节坐标、碰撞体、质量/质心/惯量，完成模型检查后再训练，不能直接把打印网格覆盖进去。

原始核对文件保存在本机临时目录 `microduck-cad-audit-20260928`，含发布元数据、主仓 STL 哈希匹配表和两个 STEP 包的逐件比较。
